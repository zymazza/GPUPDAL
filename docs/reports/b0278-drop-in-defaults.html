PDAL-GPU · B0278 · shipped GPU-class profiles

GPU by default, on GPUs we never calibrated on

Ten GPU classes were rented, calibrated with pdg calibrate, converted into shipped profiles under a 3× shipping margin and embedded in the build; a generic fallback covers other CUDA devices. Every box then re-ran the fourteen reference workflows in default mode with no local profile and nothing calibrated on it. All default-mode outputs are byte-identical to stock PDAL 2.10.0.

2.11× → 2.44×median over the boxes: default-mode geometric mean, before → shipped profiles, no calibration
2.84× → 4.32×median whole-suite speedup, before → after
2.6× → 9.0×median r6 feature extraction, before → after

1. Plain-language summary

What changed. Until now the GPU only switched on by default on the one machine we measured (the reference workstation); anyone else had to run pdg calibrate first. We rented one machine of each common GPU class, ran the calibration on each, kept only the workloads where the GPU won by at least three times at every measured size, and built those results into pdg as shipped profiles. A conservative generic profile covers CUDA GPUs we did not rent. pdg calibrate still exists — it now only tightens placement for a particular CPU or dataset — but it is no longer required.

The proof. On every rented box we then deleted the local profile, rebuilt with the shipped set embedded, and ran the same fourteen workflows in default mode as a fresh user would: no environment variables, no calibration. The table below shows before/after per GPU. Where a box's own profile was deliberately left out of the embedded set, the box exercised the generic fallback — that row shows what an unknown GPU gets.

What did not change. The bytes. Every default-mode run is compared with stock PDAL's output, metadata, order, stdout, stderr and exit status; every cell in this report passed.

2. Technical summary

  • Tier order after the embedded reference profile: local (pdg calibrate, exact machine key) → shipped (exact GPU name + compute capability + compiled CUDA toolkit; host and driver recorded, not matched) → generic (applies bounds: minimum compute capability and device memory among the contributors) → host path.
  • Shipped profiles keep a model only where device × 3 ≤ host at every measured size, envelope bounded to those sizes; the generic profile intersects the shipped models under the same 3× margin in every profile and takes the slowest device / fastest host coefficient of each term (a 5× margin left only LOF, because one rented host — the 3090's ten-core Xeon E5 v4 — halves every ratio; the ten-way intersection with worst-case coefficients is the conservatism). Both are produced by bench/report/make_shipped_profile.py from the calibrate profiles' evidence and embedded from data/placement-profiles/*.json at build time.
  • The r6 reference graph (extra_dims=all, LAZ) gained its own calibration case and model (normal-covariancefeatures-compose-extradims); a profile that carries it lifts the one-layout bound the reference profile still keeps.
  • Thin-margin models (point programs, neighborclassifier, everything below the margin) stay on the host unless a local profile admits them; the direct whole-view executors remain uncalibrated off-reference (open follow-up).
Postscript. Later on 2026-08-17 the maintainer set the shipped-profile margin to 1.7x (D0280/B0279): the ten profiles now in data/placement-profiles/ admit more than the 3x set this proof ran with (single-feature filters from 1M on every class, compose graphs from 250K, the RTX 5090's r6 composition from 1M, the RTX 3090's compose models 1M–48M). The generic fallback keeps 3x and is unchanged. The shipped-tier numbers on this page are therefore a floor for the set as built; each box's local-profile rows (a superset of the 1.7x admissions) are the nearest evidence for the wider admissions. No box was re-measured at 1.7x. Section 5's green cells and section 6's envelopes reflect the 1.7x profiles as built.

Method and caveats

  • Vast.ai containers with CPU quotas; each box's own pinned build is its baseline; only same-box comparisons are exact. Boxes ran concurrently on separate hosts.
  • Single calibrate run per GPU (three pairs per size at 250K–4M, one pair at 16M/48M); the suite figures are three-pair medians; AHN4 cells are single runs.
  • Shipped profiles transfer the host side of each decision from an EPYC/Xeon-class rented host to the user's CPU; the 3× margin is what protects that transfer. A user with a much faster CPU per core narrows the margin; pdg calibrate tightens it.
  • Two boxes show what the margin costs, on purpose. On the RTX 5090 the extradims composition measured 2.984× at 1M — under the 3× margin by 0.016 — so its shipped envelope starts at 4M, the r6 reference graph at 1M stays on the host, and the shipped-tier suite (1.84× GM) differs from the uncalibrated one (1.97×) only by that box's host-side noise (its host-only workflows moved by up to 20% between two host-only runs); its local profile, which admits 1M at 2.98×, reaches 8.66× on r6. On the RTX 3090 (ten-core Xeon E5-2673 v4 host, ~2.3–2.7× at 16M/48M) the shipped profile keeps the AHN4 tile on the host (2.4×–2.5× vs 8.1×–8.2× with the local profile, 18.8× LOF): the margin refused a thin win. Both are the tightening case for pdg calibrate, not defects.
