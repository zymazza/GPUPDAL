# filters.hag_nn

The **Height Above Ground Nearest Neighbor filter** takes as input a point
cloud with `Classification` of ground points set to 2 or a specified value.
It creates a new dimension, `HeightAboveGround`, that contains the normalized
height values.

Ground points may be generated by {ref}`filters.pmf` or {ref}`filters.smrf`,
but you can use any method you choose, as long as the ground returns are
marked.

Normalized heights are a commonly used attribute of point cloud data. This can
also be referred to as *height above ground* (HAG) or *above ground level*
(AGL) heights. In the end, it is simply a measure of a point's relative height
as opposed to its raw elevation value.

The filter finds the [count] ground points nearest the non-ground point under
consideration.  It calculates an average ground height weighted by the distance
of each ground point from the non-ground point.  The `HeightAboveGround` is
the difference between the `Z` value of the non-ground point and the
interpolated ground height.

## Example #1

Using the autzen dataset (here shown colored by elevation), which already has
points classified as ground

```{image} ./images/autzen-elevation.png
:height: 400px
```

we execute the following pipeline

```json
[
    "autzen.laz",
    {
        "type":"filters.hag_nn"
    },
    {
        "type":"writers.las",
        "filename":"autzen_hag_nn.laz",
        "extra_dims":"HeightAboveGround=float32"
    }
]
```

which is equivalent to the `pdal translate` command

```
$ pdal translate autzen.laz autzen_hag_nn.laz hag_nn \
    --writers.las.extra_dims="HeightAboveGround=float32"
```

In either case, the result, when colored by the normalized height instead of
elevation is

```{image} ./images/autzen-hag-nn.png
:height: 400px
```

## Example #2

In the previous example, we chose to write `HeightAboveGround` using the
`extra_dims` option of {ref}`writers.las`. If you'd instead like to overwrite
your Z values, then follow the height filter with {ref}`filters.ferry` as shown

```json
[
    "autzen.laz",
    {
        "type":"filters.hag_nn"
    },
    {
        "type":"filters.ferry",
        "dimensions":"HeightAboveGround=>Z"
    },
    "autzen-height-as-Z.laz"
]
```

## Example #3

If you don't yet have points classified as ground, start with {ref}`filters.pmf`
or {ref}`filters.smrf` to label ground returns, as shown

```json
[
    "autzen.laz",
    {
        "type":"filters.smrf"
    },
    {
        "type":"filters.hag_nn"
    },
    {
        "type":"filters.ferry",
        "dimensions":"HeightAboveGround=>Z"
    },
    "autzen-height-as-Z-smrf.laz"
]
```

## PDG compatibility and acceleration

PDG preserves the pinned PDAL behavior and diagnostics for every option form.
Exact CUDA paths are available for whole-view counts one through 64 with
finite binary64 coordinates, an unsigned-byte
`Classification` column, enough ground references, and a provably ordered
nearest-ground result. They query the planner-owned two-dimensional spatial
index; they do not build a private index. Ground points retain exact positive
zero. Count one uses precise binary64 subtraction in the same order as PDAL;
wider counts preserve the pinned ordered inverse-squared-distance
interpolation, strict `max_distance` cutoff, and inclusive ground bounds used
when extrapolation is disabled.

Equal-distance candidate-boundary ties, an incomplete bounded grid query,
nonfinite XY, no ground points, wider-count nonfinite Z or too few
ground references, `count >= 65`, unsupported options, and an unavailable CUDA
device retain the original host behavior. For a planner-selected resident
pipeline, a repaired host HAG column can be republished for an adjacent
point-program bridge. A following three-dimensional neighborhood stage rebuilds
the shared index instead of reusing the HAG two-dimensional index.

These GPU-native lanes remain host-selected by default. Counts five, six, and
seven also have strict opt-in mapped-source/direct-one-binary64-output
compositions;
they have no placement model or automatic selector. Current-clean
complete-process evidence
qualifies only named 1,000,002-point fixtures: B0123 records 2.518270x pinned
PDAL for the count-one direct composition, B0121 records 2.606656x for count
two, B0122 records 2.655409x for count three, and B0105 records 1.562755x for
the count-four forced fixture. B0135 records 2.930506x for the explicit
count-five direct composition. B0137 establishes exact GPU-native count-six
coverage and its dirty-snapshot 2.882422x result remains directional history;
B0138 current-clean qualifies only the named explicit count-six direct fixture
at 2.968895x. Its fresh profile identifies no reusable 5--10% endpoint surface,
so count six is sufficiently optimized for now. These explicit proofs do not
establish automatic selection or complete the broader HAG family.

B0139 measured count seven before implementation and B0140 extends the same
exact envelope to it, GPU-native inside the proved masked-2D-index envelope
with exact host repair. B0138's dirty-snapshot history aside, B0141
current-clean qualifies only the named explicit count-seven direct fixture at
2.959118x; its fresh profile identifies no reusable 5--10% endpoint surface, so
count seven is sufficiently optimized for now. It is not automatically
selected. B0143 then closes the envelope at 64, the shared index's own
neighbour cap, with a proof matrix generated over count; a dirty-snapshot
count-16 direct pair is 3.340694x. B0144 then qualifies representative counts
at 3.080885x (16) and 4.374517x (64); speedup rises with count because stock
cost grows while device cost grows far more slowly. `count >= 65` remains
pinned-host owned.

## Options

count

: The number of ground neighbors to consider when determining the height
  above ground for a non-ground point.  \[Default: 1\]

max_distance

: Use only ground points within `max_distance` of non-ground point when
  performing neighbor interpolation.  \[Default: None\]

allow_extrapolation

: If false and a non-ground point lies outside of the bounding box of all
  ground points, its `HeightAboveGround` is set to 0.  If true,
  extrapolation is used to assign the `HeightAboveGround` value.  \[Default:
  true\]

class

: Classification value of ground points.  \[Default: 2\]
